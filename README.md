# In a Grove, Again

Code and manuscript for **In a Grove, Again: Optimizing over Feasible Event Histories for
Incentive-Driven Testimony** (NeurIPS 2026, Creative AI track).

A deterministic simulator enumerates $\mathrm{Feasible}(F)$, the set of event histories
consistent with public evidence $F$. Each witness then selects the feasible history that
maximizes a transparent self-interest utility $U_i$. The framework is instantiated on three
exactly enumerated domains:

| Domain | Script prefix | Reachable states | $\|\mathrm{Feasible}(F)\|$ |
|---|---|---|---|
| *In a Grove* (Akutagawa) | `grove-*`, `optimize.mjs` | 3,631 | 11 |
| *The Ring and the Book* (Browning) | `ring-*` | 32,928 | 36 |
| Agent-operations incident | `ops-*` | 23,978 | 48 |

## Demos

Open **`index.html`**, the project page, in a browser. It introduces the paper and guides you
through the demos, each a static page in `demo/` that runs with no install and no server. The one
the paper describes is `demo/magistrate.html`.

The two paper demos each have a walkthrough video on the project page (`demo/videos/`). They are
recorded by a script, so they can be redone whenever a page changes:
`node experiment-code/recon/record-demos.mjs` (needs Chrome and ffmpeg).

## Requirements

- **Node.js** ≥ 20 (developed on v24). There is no `package.json`; the deterministic
  experiments have no npm dependencies.
- **Python 3** with `matplotlib` and `numpy` (only for the Ring learning-curve figure).
- **LaTeX** with `pgfplots` and `standalone` (figures and paper).
- **API keys** only for the LLM baselines (step 4).

All commands below are run from `experiment-code/` unless stated otherwise.

## 2. Reproduce the core results (deterministic, offline, no LLM)

| Result in the paper | Command |
|---|---|
| State counts, feasible sets, and the histories each objective selects (selection/solver table, panel a) | `node recon/benchmark-report.mjs` (or `... ops`, etc. for one domain) |
| Replay solvers (genetic search, tabular Q-learning) vs. exact optima (selection/solver table, panel b) | `node recon/solvers-report.mjs all` |
| Ring replay-learning curves (Supplementary Fig. S1) | `node recon/ring-learning-curves.mjs` then `python3 recon/fig-ring-curves.py` |
| Feature-constant sensitivity, 80.8% spread retained (Supplementary S6) | `node recon/sensitivity.mjs` (the ±0.40 row) |
| Interactive testimony / hearing figure and trace table | `node recon/fig-hearing.mjs`, `node recon/tab-hearing.mjs` |
| Deterministic constrained beam-search baseline | `node recon/beam-baseline.mjs` |

**Seeds.** All Monte-Carlo figures in the paper are drawn from `benchmark-report.mjs`, which
uses one generator and one seed across domains so that columns are comparable. The
per-domain scripts (`optimize.mjs`, `ring-optimize.mjs`) seed independently, so the same
quantity can differ slightly (e.g. grove spread survival 63.1% vs. 61.7% at $N=5000$). That
is sampling noise, not a failure to reproduce; do not mix the two sources in one table.
`sensitivity.mjs` uses its own fixed seed (16980222, $N=5000$).

**Generated data files.** Several scripts rewrite their `*-data.json` / `*-data.js` when run.
Normally only the `generatedAt` timestamp changes. Restore them with `git checkout -- <file>`
after checking.

## 4. LLM baselines (requires API keys, stochastic)

The prompting-ladder table compares LLM-written testimony against the simulator. In every
script, **no language model computes the objective**: an LLM writes an account, a
*different* LLM extracts its causal claim (wielder, manner, weapon) as JSON, and that claim is
scored by the same structural $U_i$ and simulator-decided $\mathrm{Feasible}(F)$ as the
method itself. Only generation and extraction touch the network.

### 4.1 What is already in the repository

Every LLM row in the paper comes from a committed record in `experiment-code/recon/`. Each
record stores the generated account text, the extracted claim, its causal signature, $U_i$
and whether it is feasible.

| Results | Script | Record file | Generator(s) | Accounts |
|---|---|---|---|---|
| Paper: per-model ladder for zai-glm-4.7, gemma-4-31b, gpt-oss-120b | `prompt-ladder.mjs` | `prompt-ladder-data.json` | the three models, via Cerebras | 135 |
| Paper: GPT-5 probe | `gpt5-ladder.mjs` | `gpt5-ladder-data.json` | `gpt-5`, via OpenAI | 45 |
| Paper: Claude Opus 4.8 probe | `claude-ladder.mjs` | `claude-accounts.json` → `claude-ladder-data.json` | Claude Opus 4.8 (see 4.4) | 45 |
| Not in the paper: "facts shown" baseline, the same three models | `llm-baseline.mjs` | `llm-baseline-data.json` | the three models, via Cerebras | 27 |
| Not in the paper: ops-incident LLM baseline | `ops-llm-baseline.mjs` | `ops-llm-baseline-data.json` | the three models, via Cerebras | 27 |

The ladder scripts also run a fifth rung, `shown` (facts listed as context only). The paper
reports the four rungs `instructed`, `consequence`, `selfcheck` and `selfrevise`.

Summarizing these records (per model and rung: the utility of each witness's modal claim, the
infeasible share, and the number of distinct accounts) reproduces the paper's per-model
ladder rows exactly. The "Not enforced" row (23.2%) is offline and comes from
`benchmark-report.mjs` (step 2).

> **Running a script overwrites its record file**, and with it the generations behind the
> paper's numbers. Before a rerun, copy the record aside, or restore it afterwards with
> `git checkout -- experiment-code/recon/<file>.json`.

### 4.2 API keys

Create `experiment-code/.env.local`. It is git-ignored; never commit it, and never share the
project as a zip or a synced folder, because those do not respect `.gitignore`.

```bash
# prompt-ladder, llm-baseline, ops-llm-baseline: an OpenAI-compatible endpoint, Cerebras by default.
# The variable is named OPENAI_API_KEY but holds the Cerebras key.
OPENAI_API_KEY=...            # optional OPENAI_API_KEY_2 .. _4 are rotated to spread rate limits
OPENAI_BASE_URL=https://api.cerebras.ai/v1   # default; override for another compatible host

# gpt5-ladder: generation on OpenAI, extraction on Cerebras
OPENAI_KEY=...                # a real OpenAI key
CEREBRAS_KEY=...

# claude-ladder: extraction only
# uses CEREBRAS_KEY (falls back to OPENAI_API_KEY); CEREBRAS_BASE_URL is optional
```

Load it into the shell before running any script below:

```bash
cd experiment-code
set -a; . ./.env.local; set +a
```

### 4.3 Regenerate and re-score

Settings are fixed in the scripts. Generators run at temperature 0.85 with at most 900 output
tokens; GPT-5 is a reasoning model, so it runs with `reasoning_effort: minimal` and at most
2,000 completion tokens instead. Extractors run at temperature 0.1 with at most 200 output
tokens. Each extraction uses a model other than the generator (zai-glm-4.7 by default,
gemma-4-31b when zai-glm-4.7 is the generator).

| Step | Command | API calls |
|---|---|---|
| Three-model ladder, all 5 rungs | `node recon/prompt-ladder.mjs` | 297 (162 generation + 135 extraction) |
| Only the paper's 4 primary rungs | `LADDER_CONDS=instructed,consequence,selfcheck,selfrevise node recon/prompt-ladder.mjs` | 243 |
| Facts-shown baseline | `node recon/llm-baseline.mjs` | 54 |
| GPT-5 probe | `node recon/gpt5-ladder.mjs` | 99 (54 GPT-5 + 45 extraction) |
| Claude probe: re-score the stored accounts | `node recon/claude-ladder.mjs` | 45 (extraction only) |
| Ops-incident baseline | `node recon/ops-llm-baseline.mjs` | 54 |

A full rerun is about 550 calls. The self-revise rung makes two generator calls per account
(a draft, then a revision against the facts). `LADDER_SAMPLES` (default 3) sets samples per
model, witness and rung for the ladder scripts; `BASELINE_SAMPLES` (default 3) does the same
for the two baseline scripts. For a cheap smoke test, use
`LADDER_SAMPLES=1 LADDER_CONDS=instructed node recon/prompt-ladder.mjs`.

**What counts as reproduced.** Generations are sampled, so a rerun produces different text.
Compare the summary each script prints (utility of each witness's modal claim, infeasible
share, distinct accounts) with the paper's rows, not individual accounts. Agreement is
statistical: with 3 samples per cell, one changed account moves an infeasible share by 11.1
points. Hosted model versions can also change over time.

### 4.4 Claude Opus 4.8 accounts

No script generates the Claude accounts. They were written by isolated Claude Opus 4.8
sessions, each shown only the generator prompt for one witness and rung: the public facts $F$
and that witness's self-interest, with nothing about $\mathrm{Feasible}(F)$, $U_i$, the
enumerated answer or this project. `claude-ladder.mjs` only extracts and scores them. To
regenerate:

1. Build the prompts with `genMessages(cond, witness)` in `recon/prompt-ladder.mjs`, which
   `gpt5-ladder.mjs` copies verbatim. For `selfrevise`, generate a draft from the `shown`
   prompt, then revise it with `reviseMessages(witness, draft)`.
2. Generate 3 accounts per witness (Tajomaru, Masago, Takehiro) per rung (`shown`,
   `instructed`, `consequence`, `selfcheck`, `selfrevise`), each in a fresh context.
3. Save them as `recon/claude-accounts.json`: an array of
   `{ "cond", "witness", "sample", "account" }` with `sample` 0–2, 45 entries.
4. Run `node recon/claude-ladder.mjs`.

## 5. Build the paper

The track style file `neurips_2026.sty` is not tracked. Take it from the official template,
[Formatting_Instructions_For_NeurIPS_2026.zip](https://media.neurips.cc/Conferences/NeurIPS2026/Formatting_Instructions_For_NeurIPS_2026.zip),
and put it in `paper/` (git-ignored there). Then build from `paper/`:

```bash
cd paper
pdflatex neurips_2026_v2.tex && bibtex neurips_2026_v2
pdflatex neurips_2026_v2.tex && pdflatex neurips_2026_v2.tex
pdffonts neurips_2026_v2.pdf      # body must be NimbusRomNo9L (Times); no Type 3 fonts
```

A body set in Computer Modern (`SFRM`/`CMR` in `pdffonts`) means LaTeX found some other
`neurips_2026.sty` instead of the official one; the layout and page count are then wrong.
If `pdffonts` lists a Type 3 font, run `updmap-user --enable Map=cm-super-t1.map` and rebuild.
The supplement uses the plain `article` class and builds directly, also from `paper/`:
`pdflatex neurips_2026_v2_supplement.tex`.
